# zero-memcp

我这里是一个**持久记忆体**。

你写进来的每一条都会落进本地持久记录：先写内容对象并 fsync，再追加索引记录并 fsync，
之后才返回成功。进程被杀、机器重启，下一次启动会把未封箱的写回放出来。
**`put` 返回 ok，就意味着它已经在盘上了。**

但要说准确：本机持久化不等于异地备份。整块磁盘坏掉、节点消失，内容一样会没。
那要靠 `sync` / `push` 把历史带到别的副本，那是另一件事。

## 我的形状

记忆是一棵**树**。路径就是语义：

```
daily/2026-10-31/145251.628-local.md     一条记忆切片
daily/team/chat/2026-10-31/...           某棵子树下的内容
```

没有额外的「频道」「主题」「kind 分类」。**写到哪里，就是什么。**

## 接口

MCP 只有一个工具 `term`，参数是一行 DSL：

```
term({cmd: "recall 端口为什么定1729"})
```

正文**不要拼进 `cmd`**，用 `vars` / `args`：

```json
{"cmd": "put team/chat -- $TEXT",
 "vars": {"TEXT": "一段可以含空格、换行、-- 的正文"}}
```

引用必须独占一个词。传了不用的参数会被拒绝——静默丢掉一个参数，
调用方会以为它生效了。

## 动词

```
put [<tree>] -- $TEXT        写入记忆（正文走 vars/args）
put <tree> --ref <addr>      在树里追加已有记忆的引用，不复制正文
recall <text> [--scope T]    语义回想
read <addr> [<addr>...]      读全文
grep <pattern> [--scope T]   正则扫全文
log [N]                      时间线
ls [date]                    按天列
trees <project>[@<branch>]   看树目录
remind [<tree>]              登记关注的树
since <tree> <commit>        取树差分
status                       索引规模
```

`remind` 只是**登记关注**：记下「我关心哪棵树」和当时的分支头。它不推送、不搬正文、不分配任务。
不保证实时送达。真正的恢复靠 `since`——记住你上次读到的 commit，
重连后换回差量；子树没动过时它返回空，代价是零。

## 我不做的事

- **不改已存在的文件。** 写入永远是新建。
- **不自动合并。** 冲突就报告，不猜。
- **不替你提交对外发布。** `push` 必须显式指定一个分支，且不会顺手 commit。三条传输（SSH / HTTP(S) / 本地裸仓库路径）与打包（gc）都是内置实现，不调用系统 git；root 用 `remote-key` 管私钥、`remote-secret` 管 HTTP token，内容永不回显。
- **不接受推断出来的指令。** `instruction` / `rule` 一律硬拒绝。
- **不在记忆里做保密。** 没有 `secrets` 机制——内容一旦写进来就会永久留存、
  被索引、可能被同步到别处。真正的凭证不该进这里。

## 权限

`SKILL.md` 的 `permission` 三位：

```
r-x  rwx  r--
 │    │    └─ 其他 agent
 │    └────── 主人
 └─────────── 我
```

`r` 能否被读，`w` 能否被写，`x` **能否被当作规则执行**。

**`x` 位是「资料 / 指令」的开关。** 没有 `x` 的记忆永远是资料，不可能变成规则。
记忆影响注意力，永不影响授权。
